# tgrep Search

Локальное расширение VS Code с отдельной панелью поиска по **содержимому** и именам файлов через Microsoft tgrep. В верхней части панели доступны корень исходников, путь индекса, его состояние и дата последнего успешного обновления. Индекс не строится автоматически.

Кнопка **Свернуть** скрывает настройки папок, сборки и подробное состояние. Остаются поиск и компактный индикатор с датой: **✓** — индекс готов, **↻** — занят или строится, **⚠** — нет готового индекса или ошибка. Знак **≈** означает оценку времени; подробности и пути доступны при наведении на индикатор. Кнопка **Настройки** возвращает полный вид. При загрузке панели настройки всегда скрыты; сохраняются только запрос и параметры поиска. Во время сборки можно развернуть настройки для отмены.

В настройках VS Code доступен **tgrep Search › Language** (`tgrepSearch.language`): `auto`, `en` или `ru`. Язык панели и сообщений меняется сразу, без перезапуска; запрос сохраняется. В режиме `auto` используется язык VS Code, с английским для неподдерживаемых языков. Названия команд и описания настроек следуют языку VS Code. Исходный вывод tgrep и системные ошибки отображаются без перевода.

Оформление использует мягкие границы и лёгкую полупрозрачность, цвета текущей темы и непрозрачный вариант для высокой контрастности.

English documentation: `README.md` (included in the extension).

## Установка

Требования: VS Code 1.95+, **Microsoft tgrep 1.0.5**, Python 3 с `fcntl` (macOS / Linux). Проверенная платформа — macOS arm64. Windows в этой версии не поддерживается. Ни tgrep, ни Python не включены в VSIX; Python нужен для совместимых с cron POSIX-блокировок и завершения дочернего процесса.

В VS Code выполните **Extensions: Install from VSIX…** и выберите `artifacts/tgrep-search-0.1.3.vsix`. Либо из корня репозитория:

```sh
code --install-extension artifacts/tgrep-search-0.1.3.vsix
```

Расширение устанавливается локально как `local-tools.tgrep-search`. Ничего не публикует, не меняет встроенный поиск VS Code и не подменяет ripgrep. Работает только в доверенном файловом workspace; в Remote SSH запускается на машине Extension Host, где тоже нужны tgrep и Python.

Если GUI не видит executable, задайте **tgrep Search › Executable**, например `~/.local/bin/tgrep`. По умолчанию проверяются PATH и `~/.local/bin`. Для Python есть **tgrep Search › Python Executable**. Путь — один исполняемый файл, без аргументов и shell-синтаксиса.

## Начало работы

1. Откройте tgrep в Activity Bar или нажмите **⌘⌥F** на macOS / **Ctrl+Alt+F** на Linux.
2. **Выбрать исходники…** открывает стандартный folder picker VS Code. **Проекты…** позволяет выбрать корень multi-root workspace. Выбранная папка явно показана наверху; смена активного редактора не переключает её неожиданно.
3. Независимо нажмите **Выбрать папку индекса…**. Выберите готовый внешний индекс или пустую папку. Новую папку можно создать в системном диалоге. Без выбора используется уникальная папка в global storage расширения, вычисленная по каноническому пути исходников.
4. Для нового индекса нажмите **Создать / обновить**. Для готового — достаточно дождаться проверки. Прогресс, отмена, краткий лог доступны в панели; полный лог — кнопка **Лог**, канал `tgrep Search`.
5. Введите запрос и нажмите Enter или **Найти**. По умолчанию это буквальный поиск с учётом регистра. Есть Regex и переключатель регистра. **Фильтр путей** принимает один glob, например `**/*.php` или `!**/test/**`. Для альтернатив используйте glob с фигурными скобками: `**/*.{php,ts}`.
6. Раскройте группу файла и нажмите строку результата: редактор откроет её и выделит первое совпадение. Все совпадения подсвечены в выдаче. **⌘⌥⇧F** / **Ctrl+Alt+Shift+F** и пункт контекстного меню ищут выделенный текст буквально.

Режим **Имена файлов (glob)** вызывает `--files --null`, а не поиск содержимого. Запрос здесь — glob (`**/*config*.php`); пустой запрос выводит файлы в пределах лимита. Regex в этом режиме отключён.

Привязки «канонический путь исходников → путь индекса» и выбранный проект хранятся в `workspaceState` VS Code. Они не записываются в общие настройки и не переносятся молча в другой workspace. В multi-root выбранный корень привязан также к составу workspace. Индекс внутри исходников запрещён, чтобы расширение не индексировало собственные двоичные файлы. Существующий индекс другого проекта не перезаписывается.

## Подключение готового внешнего индекса

Выберите папку исходников и независимо её существующий каталог индекса. Расширение проверит `meta.json.root_path` после разрешения symlink, формат `version=2`, полноту и обязательные двоичные файлы. Для подключения пересборка не нужна.

Путь общей блокировки вычисляется из выбранной папки индекса: `<имя индекса>-update.lock` рядом с ней. Для другого расположения есть настройка `externalLockPath`. В расширении нет заранее заданных проектов, путей к корпусам или вызовов пользовательских updater-скриптов.

## Что означает время и состояние

- **Индекс есть**: проверены принадлежность корню, полнота, размеры базовых файлов, согласованность lookup с числом триграмм, порядок времени записи. Это не полная проверка каждого posting и не обещание актуальности исходников.
- **Отсутствует / другой проект / ошибка / занят / строится** показываются отдельно. Ошибочный или неполный индекс не используется; расширение не переходит незаметно к полному обходу.
- **Подтверждено расширением**: UTC-момент после кода завершения 0 и проверки результата сборки. Он сохраняется в `.tgrep-search-completed.json` с отпечатком поколения файлов и показывается с датой и локальным временем. Начало команды и открытие панели никогда не становятся временем успешного обновления.
- **meta.updated_at, оценка завершения внешней сборки**: реальное поле tgrep в Unix seconds. В 1.0.5 оно создаётся при записи основных файлов, до окончательной записи sidecar-файлов; поэтому оно честно помечено оценкой завершения. Изменение любого файла поколения отменяет применение старой квитанции расширения.
- При отсутствии `updated_at` показывается **оценка по mtime meta.json**. Если пригодных данных нет — **неизвестно**. При блокировке или ошибке ранее известное успешное обновление сохраняется с подписью **последнее известное**.

Состояние перечитывается каждые 5 секунд, включая внешние обновления cron, и по кнопке **Проверить**. Status bar содержит краткое состояние и время (≈ означает оценку); tooltip показывает оба пути и полную дату. Нажатие открывает панель; соседняя кнопка обновления запускает сборку.

## Сборка, скрытые файлы и блокировки

Сборка эквивалентна:

```sh
tgrep index <исходники> --hidden --exclude .git --index-path <индекс>
```

`.gitignore` сохраняет семантику tgrep; `--no-ignore` не применяется. Вне Git-репозитория tgrep может не учитывать `.gitignore` — это его штатная семантика. Скрытые `.settings.php` и `.default` включаются, `.git` исключается.

Поиск содержимого эквивалентен:

```sh
tgrep --index-path <индекс> --color=never --json --line-buffered \
  --case-sensitive --fixed-strings --regexp=<запрос> -- <исходники>
```

Все аргументы передаются массивом через `spawn` / `subprocess.Popen`, без shell. Пробелы, Unicode, `$()` и ведущий дефис не интерпретируются оболочкой. **Поиск не передаёт `--hidden`**: в tgrep 1.0.5 этот флаг обходит индекс. Расширение не запускает `serve`; наличие `serve.json` блокирует дисковый режим, поскольку tgrep иначе автоматически подключается к серверу. При подключении такого индекса сначала остановите сервер и уберите его устаревшие метаданные самостоятельно.

Python helper удерживает общие flock-блокировки на время поиска и исключительные на время сборки. Используются два соседних файла: `<имя индекса>.tgrep-search.lock` и `<имя индекса>-update.lock`. Поэтому даже чтение индекса требует возможности открыть эти lock-файлы на запись (их создание не меняет сам индекс). Сборки разных индексов могут выполняться параллельно. Файлы блокировки остаются на диске; их существование не означает занятость — проверяется именно `flock`.

Для внешнего updater с другим путём укажите **tgrepSearch.externalLockPath** в настройках выбранного workspace folder. Внешний updater должен держать **исключительный `fcntl.flock` на этом же файле всё время работы `tgrep index`**. При nonblocking lock внешний updater может пропустить запуск, если в этот момент идёт поиск.

Перед сборкой создаётся `.tgrep-search-building.json`. При ошибке, отмене или аварийном завершении он остаётся: индекс не считается готовым до следующей успешной сборки расширением. Предыдущая успешная дата не перезаписывается. Сборка выполняется на месте; прежнее поколение не резервируется и может стать недоступным после неудачной попытки. Повторное обновление восстанавливает индекс. Для посторонней непустой папки без метаданных tgrep сборка запрещена.

**Ограничение внешней записи:** произвольный `tgrep index`, запущенный без согласованного flock, нельзя атомарно синхронизировать средствами расширения: tgrep 1.0.5 сам такой lock не берёт. Проверка времён/размеров перед поиском и отпечатка после него обнаруживает многие такие изменения и отбрасывает выдачу, но не заменяет общий lock. Для гарантии отсутствия чтения частично переписанного индекса запускайте внешние обновления через согласованный updater. Не используйте `serve` для этого индекса.

## Ограничения первой версии

- Поиск по сохранённым файлам, не по несохранённым редакторам. Добавление и изменение файлов могут давать пропуски до следующей индексации. Индекс не обеспечивает мгновенную актуальность.
- Только однострочные запросы. Regex следует синтаксису tgrep. Нет массовой замены, слежения за изменениями и сервера.
- До 1000 строк по умолчанию (`maxResults`, максимум 10000), до 8 MiB stdout (`maxOutputMB`, максимум 32). При достижении лимита процесс останавливается, выдача помечается неполной. Даже ровно достигнутый лимит помечается консервативно. Одна JSON-запись свыше 1 MiB вызывает понятную ошибку.
- Вывод разбирается асинхронно по чанкам; результаты публикуются после завершения или лимита. Это ограничивает память и позволяет отмену без тысяч сообщений webview. Текст предпросмотра ограничен 2000 символами на строку.
- Отмена завершает группу процессов; через 2 секунды применяется SIGKILL, если SIGTERM не сработал. Закрытие Extension Host также завершает запущенную работу. Новая генерация запроса не принимает запоздалые результаты старой.
- Смещения JSON считаются байтами UTF-8 декодированного текста и преобразуются в UTF-16. Проверены кириллица и emoji. Для нестандартных кодировок навигация зависит от совпадения декодирования tgrep и VS Code. Имена файлов с невалидными UTF-8 байтами не поддерживаются.
- Не проверены Windows, сетевые файловые системы с нестандартной семантикой flock, Remote SSH и другие версии tgrep. Для них работоспособность не обещается.

## Разработка и проверки

```sh
npm ci
npm test
npm run test:integration
npm run test:ui
npm run test:host
npm run package
```

`test:integration` использует реальный tgrep из `TGREP_EXECUTABLE` или `~/.local/bin/tgrep`, создаёт маленький корпус под `.scratch` и удаляет его. Тесты не обращаются к внешним проектам.

`test:ui` требует установленный Google Chrome; запускает headless Playwright для настоящих HTML/CSS/JS панели со stub-мостом VS Code. Проверяет Enter, Unicode-подсветку, группировку, сообщения перехода, отдельные кнопки директорий, режим имён файлов, состояние сборки, узкую панель 280 px и XSS/CSP. Скриншот — `artifacts/panel-ru.png`.

`test:host` запускает установленный VS Code с отдельными user data и extensions под `.scratch/host`; личный профиль не меняется. Путь можно переопределить через `VSCODE_EXECUTABLE`. Проверяются настоящий Extension Host, сборка и квитанция, поиск выделения, DOM webview через CDP, поиск кнопкой, отсутствие совпадений и клик с проверкой UTF-16-выделения в настоящем редакторе. Скриншот — `.scratch/host/vscode-host.png`. Для разработки также есть F5-конфигурация.

Границы UI-проверки: системные folder picker-диалоги, физическая комбинация клавиш и multi-root переключение вручную не проверялись. Кнопки выбора, светлая и тёмная темы, узкая панель и режим высокой контрастности проверены браузерным тестом; принадлежность индекса — отдельными тестами. Enter проверен в Chrome со stub-мостом, реальная навигация, скрытые по умолчанию настройки и переключение языка — в VS Code. Другие платформы не проверены.
