# tgrep Search

![tgrep Search в VS Code: результаты поиска по индексу и выделение кода в демонстрационном проекте](docs/images/search-preview.png)

## Quickstart — быстрый старт

1. Установите **[Microsoft tgrep 1.0.5](https://github.com/microsoft/tgrep/releases/tag/v1.0.5)** и добавьте его в PATH.
2. В **VS Code 1.95+** выполните **Extensions: Install from VSIX…** и выберите пакет для своей ОС и процессора. Сборки доступны в [артефактах GitHub Actions](https://github.com/disqurell/tgrep-search-vscode/actions/workflows/build.yml); установки из Marketplace пока нет.
3. Откройте **tgrep Search** на боковой панели или нажмите **Cmd+Alt+F** / **Ctrl+Alt+F**.
4. Раскройте **Настройки**. Выберите **папку исходников** и отдельно **папку индекса вне исходников**. Можно оставить предложенную папку индекса.
5. Нажмите **Создать / обновить**, дождитесь ✓, введите запрос и нажмите **Enter**. Нажмите на результат, чтобы открыть строку в редакторе.

Достаточно VS Code и tgrep. Если tgrep не найден, укажите путь к исполняемому файлу в настройке **`tgrepSearch.executable`**.

## Поиск

- Ищите **содержимое файлов**: буквальный текст или регулярное выражение, с учётом регистра или без него.
- Ограничивайте пути через **glob**, например `**/*.ts` или `!**/test/**`.
- Переключитесь на **Имена файлов (glob)** для поиска по имени.
- Ищите выделенный текст через **Cmd+Alt+Shift+F** / **Ctrl+Alt+Shift+F** или контекстное меню редактора.

Настройки по умолчанию свёрнуты. Над поиском всегда видны **✓ и время последнего успешного обновления индекса**; **≈** обозначает оценку времени внешнего обновления. Раскройте настройки, чтобы увидеть обе папки, обновить индекс или выбрать проект в multi-root workspace.

## Настройки

Откройте настройки VS Code и найдите **tgrep Search**.

| Настройка | Назначение | По умолчанию |
| --- | --- | --- |
| `tgrepSearch.language` | Язык панели: `auto`, `en`, `ru` | Язык VS Code |
| `tgrepSearch.executable` | Путь к исполняемому файлу tgrep | `tgrep` |
| `tgrepSearch.maxResults` | Максимум строк или файлов в выдаче | `1000` |
| `tgrepSearch.maxOutputMB` | Максимальный объём выдачи в MiB | `8` |
| `tgrepSearch.externalLockPath` | Общая блокировка с внешним updater | Рядом с индексом |

## Что нужно знать

- **Обновляйте индекс после изменения файлов.** Поиск читает сохранённые файлы; индексация запускается вручную.
- Скрытые файлы включаются при сборке; правила игнорирования tgrep сохраняются.
- Готовый дисковый индекс можно подключить без пересборки. Он должен принадлежать выбранной папке. Для cron и других внешних обновлений нужна [общая блокировка](docs/indexes.md#hidden-files-and-safe-rebuilding).
- Сборка обновляет индекс на месте. После ошибки или отмены снова нажмите **Создать / обновить**, прежде чем искать.
- Поддерживаются однострочные запросы, без замены. При достижении лимита выдача помечается неполной.

Есть пакеты для **macOS, Linux, Alpine и Windows**, для **x64 и ARM64**. Windows пока экспериментален: проверка исполнения в нативной среде не завершена. В Remote/WSL пакет и tgrep нужны на стороне Extension Host; браузерный VS Code не поддерживается. [Требования к платформам и выполненные проверки](docs/development.md#platforms) — на английском.

## Разработка

```sh
npm ci
npm test
npm run package
```

Для сборки нужны Node.js и C-компилятор. VSIX появится в `artifacts/`. Подробности на английском: [сборка и тесты](docs/development.md#build-and-test), [устройство индекса и внешние обновления](docs/indexes.md).
